# Changelog

## 1.1.0 (unreleased)

- **Breaking:** the project is renamed from AML (AudioMIDI Link) to Cricket (Cricket MIDI). Crates are now `cricket_core`, `cricket_engine`, `cricket_cli`, and `cricket_gui`; the CLI binary is `cricket`; the app identifier is `se.dpmstudios.cricket`. The protocol keeps the name AML (AudioMIDI Link), with Cricket as its reference implementation; its first official version is AML v1 (spec: `docs/aml-v1-spec.md`), with wire version nibble `1` in the packet header, so it does not interoperate with earlier AML builds. The legacy prototype phy module is now `phy_legacy`. GUI settings live in a new `cricket` config directory; settings from AML builds are not migrated.
- MIDI/AML decoding tolerates a wide input level range (−30 dB to 0 dB relative to transmit level) via level-independent tone detection and a silence floor.
- Link loss and panic use one fail-safe path: Sustain off and All Notes Off are sent once, without duplicate bursts.
- Repeated on-air copies of the same packet are suppressed within a short time window; dedup state resets when the link is declared dead.
- False preamble locks and missed body symbols resync without discarding already-received audio.
- TX prioritizes panic and note-offs over new notes. Each released note's note-off is repeated up to 6 times in idle slots, so a lost note-off does not leave the note hanging; heartbeats are sent only when fully idle.
- A note released and struck again quickly (a trill or roll) stays in order, so it ends released. Panic discards note-ons that are still queued.
- Sustained fast traffic keeps queued note-ons under a bounded latency; queued note-ons beyond that budget may be dropped, but note-offs and panic are not, and a chord of up to 4 notes is never dropped.
- If the audio input device stops delivering samples while the link is up, All Notes Off is sent and an audio-input-stalled alarm is raised.
- Selected audio and MIDI devices are remembered by name across restarts and re-plugging.
- The UI unlocks controls when an engine worker stops and allows “none” for optional MIDI in/out.
- `aml_cli loopback` and the GUI self-test report measured MIDI-in to MIDI-out note-on latency (mean, 95th percentile, and jitter) while playing and releasing notes, instead of a theoretical airtime. The self-test no longer blocks the UI.
- While encoding, the UI shows how many messages are queued and how late the oldest one already is (its wait plus the audio buffered ahead of it). A panic button sends All Notes Off. Profile hints say when to use Fast and when to use Robust.
- Continuous integration runs `cargo test`, `clippy`, and `fmt` on GitHub Actions.
- `aml_core` builds as `no_std` + `alloc` (with `--no-default-features`) so the modem can run on microcontrollers such as ESP32-S3, RP2350, and STM32. WAV file I/O and the legacy V1 phy stay behind the default `std` feature. CI checks the build for `thumbv8m.main-none-eabihf`.
- A false preamble lock whose body fails to decode no longer swallows a real packet that starts inside it: the receiver rewinds and re-scans the buffered audio (MFSK profiles).
- The CLI takes a global `--profile` option for every command; `cricket loopback --profiles a,b,… --notes N` measures several profiles in one run.
- **Provisional** AML v1 profiles (spec §6.5; may still change in a later revision): `ltc`, `ltc2400`, `ltc4800`, and `ltc9600` using an LTC-style biphase-mark code (~22 ms mean NoteOn latency at 4800 bit/s). They need a dedicated, clean line: no EQ, compression or limiter; see `docs/proposals/ltc-bmc.md`.
- **Provisional** (spec §6.5): `ltc_fec`, `ltc2400_fec`, and `ltc9600_fec` profiles: the LTC-style phy with the Reed–Solomon coded body (+5 ms airtime at 4800 bit/s, ~26 ms mean NoteOn latency in loopback). In the simulator a 1 ms / 3 ms dropout is survived by 96 % / 92 % of packets (`ltc`: 22 % / 0 %) and 100 clicks/s at +12 dB by 93 % (`ltc`: 69 %); see `docs/proposals/ltc-bmc.md` §9.
- The LTC receiver makes soft decisions: a sync correlator that keeps running during a packet (a false lock can no longer hide a real packet), integrate-and-compare bit decisions on a tracked bit grid, per-nibble reliability, and erasures for dropouts. At 4800 bit/s it delivers 99.8 % of packets at 4 dB SNR (before: 44 %) and no simulated condition got worse; CPU cost rises from ~18 to ~60 ns per sample on the host, about the same as the MFSK receivers' preamble search after its speed-up below (~14 ns per sample idle, ~64 worst case).
- **Breaking:** `robust`, the default profile, now sends a Reed–Solomon coded body (two RS(11,7) codewords over GF(16), whitened, spec §4.6) **once** instead of the uncoded body twice, and finds the preamble from all 4 symbols together (any 2 may be missed). It cuts airtime per message from 273 ms to 175.5 ms and mean NoteOn latency in loopback from ~345–360 ms to ~265–270 ms (p95 ~475–500 → ~340–350 ms), and delivers as often or more in every simulated channel except dropouts of ≥ ~50 ms (e.g. −3 dB SNR: 97 % vs 33 %; 5 % wrong tones: 97 % vs 65 %). Both ends must be updated together. The previous behaviour is the new profile **`robust_repeat`**, the choice for lines with glitches or dropouts of ~50 ms or more (60 ms dropouts: 92 % vs 72 % delivered). The name `robust_fec`, which this profile had during development, is still accepted and means `robust`. See `docs/proposals/fec.md`.
- `robust_repeat` also finds its preamble from all 4 symbols together (one may be missed) instead of requiring the first; the wire format is unchanged. It delivers as often or more in every simulated channel (−3 dB SNR: 33 % → 46 %; 5 % wrong tones: 65 % → 75 %; 30 / 60 ms dropouts: 96 / 90 % → 98 / 92 %). Fast keeps first-symbol detection (its 2-symbol preamble is too short).
- The spec (`docs/aml-v1-spec.md`) now covers every profile, including the body FEC, the packet validation rules a receiver must apply, the LTC profiles (provisional), and test vectors that a test keeps in sync with the code. The GUI profile selector and the CLI help list `robust`, `robust_repeat`, `fast` and the LTC profiles.
- The FEC profiles (`robust`, `ltc_fec`, `ltc2400_fec`, `ltc9600_fec`) are much harder to fool with foreign audio: the decoder only offers the CRC candidates within the code's error budget, rejects out-of-range payloads, and the coded body is whitened (a wire change for these profiles: both ends must run this version). Worst measured case before: one false message per ~530 h of MFSK traffic into `ltc2400_fec`, and per 2–22 h of traffic from a transmitter without FEC on the same phy (e.g. uncoded Robust repeat into `robust`); now ≥ 89 years in every measured case (target: one per 10 years), with packet delivery unchanged within ~0.5 % in the key conditions. See `docs/proposals/fec.md` §9.
- The MFSK receivers search for a preamble with ~15× less CPU (in silence or noise: ~220 → ~15 ns per sample on the host; ~64 ns worst case, on unrelated MFSK audio). The receiver checks the expected tone before running the 16-tone bank; with first-symbol detection the results are bit-identical.
- **Breaking (wire format):** AML v1 now carries every MIDI 1.0 channel message on all 16 channels (Note On/Off with release velocity, poly and channel aftertouch, Control Change including channel mode messages, Program Change, Pitch Bend) plus Song Position, Song Select and Tune Request, in one `Midi` message type; previously only Note On/Off and Program Change on channel 1. SysEx other than MSC, MIDI Clock and other real-time messages, and MIDI Time Code are deliberately not carried (they need timing a packet link cannot give and would delay everything else). The packet `SEQ` is now a 2-bit counter with six reserved zero bits, which keeps the FEC profiles' protection against false messages within 0.5 bit of before despite the larger message set (worst measured case: one false message per 62 years for a misconfigured transmitter, 196 years for natural audio; target 10 years).
- **MIDI Show Control works end to end:** the decoder outputs real MSC SysEx (previously MSC was decoded but never sent to MIDI out), and the encoder accepts MSC SysEx from MIDI in. GO / STOP / RESUME / LOAD / GO_OFF / GO/JAM_CLOCK with cue numbers 0–999.9 (one decimal) and cue lists 1–15, FIRE, ALL_OFF, RESTORE, RESET, STANDBY ±, SEQUENCE ±, the clock and MTC-chase commands, and OPEN / CLOSE_CUE_LIST are carried. The MSC device ID and command format are decoder settings (default all-call `0x7F`, Lighting `0x01`; `cricket decode --msc-device-id/--msc-format`, GUI settings). An MSC message that cannot be carried exactly (e.g. cue 12.345, a cue path, TIMED_GO) is dropped with an alarm instead of being sent as a different cue.
- Controller, pitch-bend and aftertouch streams are coalesced while waiting to be sent (latest value wins): a fader sending 200 values/s no longer builds up seconds of backlog, its final value arrives within about two message times, and notes are delayed by at most one controller update of their own channel. Bank Select, RPN/NRPN, Data Entry and Program Change keep their order; a NoteOff never overtakes a sustain pedal it was played after; All Notes Off / All Sound Off go out with Panic priority; MSC goes out with NoteOff priority.
- The fail-safe burst (link dead, audio input stalled, Panic) now sends Sustain off and All Notes Off on all 16 channels, and re-centers pitch bend on channels the decoder left bent.
